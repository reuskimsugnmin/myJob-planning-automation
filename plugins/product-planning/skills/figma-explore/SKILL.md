# Figma Explore (대화형 Figma 읽기 탐색)

Figma "읽기"의 단일 소스. 핵심 목표는 **토큰/컨텍스트 과부하 방지**와 **사람 확인 게이트**다.
이 방법론의 게이트·직렬 루프는 **메인 컨텍스트(이 스킬을 호출한 스킬)** 가 소유한다.
페이지별 대량 노드 읽기로 컨텍스트가 크게 오염될 때만 `research-agent` 에 **단일 페이지씩** 격리 위임한다(여전히 직렬).

## 게이트 0 — 탐색할 페이지 선정 (필수 HITL)
- Figma 파일 링크 안에는 페이지가 **복수**로 존재한다. 파일 전체를 보지 않는다.
- 사용자가 탐색할 페이지를 **명시했으면** 그 페이지들만 대상으로 한다.
- **명시하지 않았으면, 임의로 시작하지 말고 반드시 어떤 페이지를 탐색할지 사용자에게 질문하고 확인받은 뒤 착수**한다.
- (선택) `sources.json` 의 `figma.explore_pages` 힌트가 있으면 후보로 제시하되, 최종 범위는 사용자 확인을 따른다.

## A. 인덱스만 먼저
- `get_metadata` 로 파일의 **페이지/최상위 프레임 인덱스만** 파악한다. 페이지 본문을 한꺼번에 읽지 않는다.

## B. 목표 기반 1차 선정 (탐색 순서)
- 게이트 0에서 확인된 페이지 범위 안에서, `00-project-brief.md` 의 이번 작업 목표를 근거로 **선제적으로 먼저 볼 페이지의 순서**를 결정한다. 선정 근거를 한 줄로 남긴다.

## C. 콘텐츠 노드 우선
- 단일 페이지에 진입하면, 그 페이지로 스코프한 `get_metadata` 로 **콘텐츠가 그려진 노드(자식 있는 프레임·명명된 섹션) 위치부터** 빠르게 식별한다.
- 그 다음 **콘텐츠 노드에만** `get_design_context` / `get_screenshot` 을 적용한다. 빈·장식 노드까지 전체 트리를 읽지 않는다.

## D. 엄격한 직렬 처리
- 페이지를 **하나씩 순차**로만 처리한다. 한 페이지 탐색이 끝나야 다음 페이지로 넘어간다.
- **Figma 작업은 절대 병렬로 진행하지 않는다**(같은 파일에 복수 에이전트 동시 디스패치 금지).

## E. 콘텐츠 파악
- 페이지 내 **플로우차트 · 기획 텍스트 · 화면 이미지** 등을 읽어, 레거시 제품 서비스가 어떻게 기획되어 있는지 파악한다.
- 프로젝트 유형: 레거시 개선이면 `figma.legacy_files`, 신규면 `figma.reference_files`.

## F. 완료 체크포인트 (필수 HITL)
- B에서 정한 목표 범위의 페이지 탐색·레거시 파악이 1차 완료되면:
  1. **작업 완료를 반환**하고,
  2. **남은 페이지/작업이 무엇인지 사용자에게 알리고**,
  3. **마저 진행할지 확인받아** 남은 작업 수행 여부를 결정한다.

## G. KB 적재
- 파악한 레거시 정책/기획을 출처 **`figma:<file-key>#<node-id>`** 로 인용해, 노션·로컬과 동일하게 `knowledge-base` 스킬 스키마로 저장한다.

## 원칙
- 출처 없는 단정 금지. 전체 노드를 무차별로 읽어 토큰을 낭비하지 않는다.
- 게이트 0(페이지 선정)·F(완료 체크포인트)는 생략 불가.
