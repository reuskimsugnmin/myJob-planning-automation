# Design Description (디스크립션 작성·동기화)

워크플로우 12단계. 완성된 디자인을 보고 **뱃지별 기획 디스크립션**을 작성하고, 그 내용을 **실제 디자인에 동기화**한다.
**Description만 수정하고 디자인에 미반영하는 것은 금지** — 두 소스의 불일치는 개발·QA·운영에 잘못된 정보를 준다.

> Figma 노드 조작·폰트 로딩·심볼 INSTANCE 처리·스크린샷 검증 등 "쓰기" 원시는 **`figma-design` 스킬**(특히 §E 폰트·§G 심볼)을 따른다. `use_figma` 전 `/figma-use` 필수.
> 모드: `--scan`(변경 계획만 분석·보고) → 검토 후 `--apply`(적용). 플래그 없으면 전체.
> 상세 레벨: **`--dev-detailed`(기본)** = 개발 착수용 — §4-D 추가 섹션(`[상태]`·`[데이터]`·`[인터랙션]`·`[연동]`·`[엣지/예외]`·`[수용 기준]`)까지 채운다. **`--standard`** = 간략(의도 중심, §4 기본 섹션만, opt-in).

## 0. 핵심 원칙
**커버리지 — 모든 화면.** 대상 페이지의 **모든 SECTION 화면**에 Descriptions 프레임·뱃지가 있어야 완료다. 일부 화면만 작성하고 끝내면 **미완료**이며, 미처리 화면 목록을 사용자에게 보고한다(특정 화면을 의도적으로 제외하려면 사용자 확인). `.md` 파일만 쓰고 캔버스에 뱃지/annotation을 안 만든 화면은 미처리로 본다.

디자인 **정수 뱃지 N** = Description **annotation-frame N**. annotation N의 제목·본문은 **뱃지 N이 화면에서 가리키는 바로 그 UI 요소**를 설명한다. 개수만 맞추는 게 아니라 **무엇을 가리키는지**가 맞아야 한다(개수 OK인데 의미 어긋남이 가장 잦은 결함).

Description 프레임 구조(운영 양식): `Description > annotation-frame × N`. 각 `annotation-frame` 은 텍스트 3개 — **노드명 고정**: `"1"`(뱃지 번호) · `"Section Title.."`(제목) · `"Lorem ipsum..."`(본문). 새 annotation-frame 을 만들 때도 이 노드명·구조를 그대로 따른다.

### 0-A. 정본 구조 불변식 (재발 방지 — 반드시 준수)
> 과거 사고: 디스크립션을 정본 템플릿 clone 없이 **임의의 새 패널로 발명**했고, 그 전에 "lo-fi 잔재" 정리 중 디스크립션 구조가 붙은 SECTION을 **삭제**해 과거 픽스를 날릴 뻔했다. 아래를 반드시 지킨다.
- **정본 템플릿 clone 필수 · 레이아웃 발명 금지.** Description/annotation-frame/label-group 은 새로 디자인하지 말고 **기존 정본 노드를 clone**해 텍스트(`"1"`/`"Section Title.."`/`"Lorem ipsum.."`)만 교체한다. 임의의 새 패널·뱃지 모양 생성 금지.
- **보호 레이어 · 삭제 금지.** `Description`·`annotation-frame`·`label-group`·`text-area`·`SB_Templates` 행은 cleanup/정리 단계에서 **삭제하지 않는다.** "낡은 lo-fi"로 보여도 주석 레이어·과거 픽스가 함께 묶여 있을 수 있다. 삭제가 필요하면 대상이 디스크립션 구조/과거 픽스가 아님을 확인하고 애매하면 **사용자 확인**(`prd-sdd-editing` 의 ID안정성·유실방지 불변식을 디자인에도 적용).
- **작업 전 재로드.** 디스크립션 작업 시작 시 이 스킬 + 정본 구조 메모리를 먼저 로드해 임의 구조 생성을 차단한다. `.md` 백업이 내용 진실 소스이므로 캔버스 유실 시 .md로 복구한다.
- **3-set 행 배치(운영).** 한 화면 행 = `SB_Templates`(헤더 밴드) **위에** 디자인 SECTION(폭 1375·`#000000 10%`, 디자인 프레임 + 뱃지 **섹션 최상위 z**·디자인과 분리) + **우측** `Description`. 화면 추가는 이 행을 clone해 헤더·프레임·뱃지·annotation 내용만 교체.

## 1. 뱃지 수집 — 두 구조 모두 (누락 1순위)
뱃지 번호는 한 화면에 **두 구조로 섞여** 존재한다. 반드시 둘 다 센다:
- `label-group` 래핑 프레임(보통 `label-group > text-area > TEXT`)
- 단독 `text-area`

한 구조만 세면 누락·중복(과거 text-area 누락으로 뱃지 5·6·7 중복 추가 사고). **node id로 dedup**(중첩 이중카운트 방지), 같은 번호가 서로 다른 노드 2개면 진짜 중복 → 나중(높은) ID 삭제·원본 유지. **노출(visible) 뱃지만** 매칭 대상.

## 2. 정수 뱃지 vs 서브 뱃지
- **정수 뱃지(1,2,3…)** → 각각 독립 `annotation-frame`.
- **서브 뱃지(2a, 3-1, 3b 등)** → 독립 프레임 **금지**. 부모 정수 annotation 본문에 `(2a) 설명` 세부 항목으로 접는다. **디자인의 서브 뱃지는 그대로 둔다.**

## 3. 뱃지 → 요소 매핑 (가장자리 거리 + 컴포넌트 후보)
각 뱃지가 가리키는 대상은 **bbox 가장자리(edge) 거리가 가장 가까운 노출 요소**다. **중심좌표 거리로 판단하지 않는다.**
- **반드시 edge 거리.** 넓은 버튼·카드는 중심이 멀어도 가장자리는 가깝다. 중심 거리로 보면 옆 텍스트로 오매핑(예: 와이드 CTA 우측 끝에 붙은 뱃지가 위쪽 금액 텍스트로 오매핑).
- **후보에 인터랙티브 컴포넌트 포함 — 아이콘 전용 버튼도 반드시.** TEXT뿐 아니라 버튼·INSTANCE·토글·탭·칩(이름에 `button/btn/cta/toggle/tab/chip` 또는 내부 라벨 텍스트), 그리고 **라벨 없는 아이콘 인터랙션**(`call/phone/message/chat/favorite/share/gps` 등)도 후보. 아이콘 버튼을 빼면 옆 텍스트로 오매핑되고 인접 뱃지까지 한 칸씩 밀린다.
- 매핑 결과로 annotation **제목(요소명)·본문(요소 설명)**을 쓴다.
- 세로로 쌓인 상태 헤더 vs 바로 아래 카드는 한 칸 어긋나기 쉬우니 edge 결과를 **`get_screenshot` 으로 교차 확인**.

## 4. annotation 본문 형식 (정본 — 일관성 필수)
**제목(Section Title) = 가리키는 요소명.** **순수 요소명만 쓴다 — `(CTA)`·`(칩)`·`(입력)`·`(스피너)` 같은 컴포넌트 유형 괄호 수식 금지**(예: `다음 (CTA)`✗ → `다음`✓, `월 납입 금액 (입력)`✗ → `월 납입 금액`✓). 본문 규칙:
- **★ Figma 노드/컴포넌트 이름 금지(가장 잦은 오염).** `ico/.../call`·`img_..._thumb`·`Frame 378`·`UI/Button/rounded`·`Group 12`·`Property 1=…` 전부 제외. **사용자가 보는 기능/대상**으로 쓴다(예: `…/call 아이콘` → `전화를 거는 버튼`). 노드 id가 필요하면 본문이 아니라 로그에.
- **(a) 역할 문장** — 첫 줄에 요소 역할 1문장, **라벨 없이**. `[개요]` 머리 금지(제목과 중복).
- **(b) 세부 항목** — 해당하는 것만, **대괄호 섹션 라벨 `[항목]`** 로 구분. **`[항목]`은 한 줄 단독으로 쓰고 다음 줄부터 `- 값` 불릿.** 라벨과 값을 한 줄에 붙이는 인라인 금지 — `Validation: 값`✗ 은 물론 **`[Validation] 값` 처럼 대괄호 라벨 뒤에 값을 같은 줄에 붙이는 것도 금지✗**. 올바른 형식:
  ```
  [Validation]
  - 최소 1만원 ~ 최대 300만원
  ```
  표준 라벨·순서: `[노출 조건]` `[Default 상태]` `[컴포넌트 상태]` `[플랫폼 분기]` `[Action]` `[Validation]` `[에러 케이스]` `[미노출 항목]` `[미확정]`. 조건은 `[필드]=[값]`, 정책 참조는 `(P-XX A안)`·`(US-XXX)`. 도메인 값은 `00-project-brief.md`(플랫폼/필드/에러 표준)에서. **작성 시 사용자 픽스 화면 본문을 서식 exemplar로 삼는다**(자의 압축 금지).
- **(c) `[Default 상태]` — 인터랙티브 컴포넌트는 필수.** 버튼·CTA·토글·체크박스·탭·입력이면 진입 시 최초 상태와 전이 조건을 명시: 상시 Enabled(`- Default: Enabled (상시 활성)`) 또는 조건부(`- Default: Disabled → [약관 동의]=true & [필수 입력]=완료 시 Enabled`). ON/OFF·선택은 최초값도. 디자인의 시각 상태(흐림/비활성색)와 일치.
- **(d) 서브 뱃지** — `[세부]` 섹션에 `(Na) 요소명: 설명` 한 줄씩.
- 플로우차트(CONNECTOR 1개 이상)면 `[플로우]` 항목 추가. 숨김 노드(`visible=false`)는 `[미노출 항목]`.
- 짧은 단일 요소는 (a) 역할 문장만으로 충분(섹션 라벨 없이 평문 1~2문장 허용).

`${CLAUDE_PLUGIN_ROOT}/templates/design/design-description.template.md` 의 슬롯 포맷을 따른다.

### 4-D. 개발자 상세 모드 (`--dev-detailed`)
개발자가 화면만 보고 구현할 수 있게, §4 기본 섹션에 더해 **요소별로 해당하는 것만** 추가한다(표준 라벨 양식 그대로 — `[항목]` 단독 줄 + `- 값` 불릿).
- **`[상태]`** — 컴포넌트의 **모든 상태 + 전이 트리거**(default/focus/filled/selected/loading/error/empty/disabled). 단순 enabled/disabled면 §4 `[Default 상태]` 한 줄로 충분, 다상태면 여기서 펼친다. 예: `- Error: 응답 실패 시 테두리 red + 인라인 배너`.
- **`[데이터]`** — 동적 값의 `필드: 타입, 출처, 범위/포맷, 기본값`. 예: `- amount: number(원), 사용자 입력, 1만~300만, 천단위 콤마, 기본 0`.
- **`[인터랙션]`** — 제스처 → 결과 + **이동 화면 + 전달 파라미터**. 예: `- 탭 → P-03 (params: productId, amount, term)`.
- **`[연동]`** — 흐름·분기만(엔드포인트·성공/실패→다음 화면). **데이터 계약·요청/응답 스키마는 적지 말고 `(SDD §x)`로 링크**(중복·비대화 방지).
- **`[엣지/예외]`** — empty·네트워크 오류·타임아웃·권한 거부·overflow·긴 텍스트 잘림.
- **`[수용 기준]`** — Given/When/Then 한 줄 + `(US-n)` 연결.
- **지어내기 금지.** 미정 계산식·엔드포인트·필드명은 **`[미확정]`** 으로 표시하고 SDD/사용자 결정에 위임(`⛳DECISION`). 자료 없는 단정 금지.
- **경계**: UI 상태·인터랙션·카피·검증 시점은 여기, **데이터/API 계약은 SDD**(`sdd-author`+`tech-registry`). 디스크립션은 SDD를 링크만.

## 5. 작성 검증 (2단계 — 둘 다 필수)
- **(A) 개수**: `annotation-frame 수 == 정수 뱃지 수`. 각 서브 Na는 부모 N 본문에 `(Na)` 줄 존재.
- **(B) 의미(누락 잦음)**: 각 뱃지 좌표 **최근접 요소 == annotation 제목**인지 `get_screenshot` 교차검증. 다르면 정정. 개수만 맞고 헤더↔카드가 뒤바뀐 통과를 막는다.
- 자동 판정 가능한 것(개수·서브 접힘·`[개요]` 잔존·인라인 라벨)은 스크립트로, 의미(제목=대상)는 `semantic` 표 + 스크린샷으로 사람이 대조.

## 6. 디자인 동기화 (Description → Figma)
Description write 작업은 **디자인 동기화까지 완료해야 작업 완료**다.

| Description 내용 | 디자인 액션 |
| --- | --- |
| "[요소]: X 조건 시 미노출" | 노드 `visible=false` |
| "[요소]: Y 조건 시 노출" | 노드 `visible=true` |
| "표기/노출 필수" 명시 + 노드 특정 가능, 현재 미반영 | `visible=true` 적용 (**SKIP 금지**) |
| 컴포넌트 Default 상태(예 Default=Disabled) | 명시 상태 variant로 `setProperties` swap. variant 없으면 visible/스타일, 구조 불일치 시 SKIP+수동 |
| 텍스트 값 명시 | TEXT 노드 `characters` 업데이트 |
| 조건부 노출(`[필드]=[값]`) | conditional 표시 후 기획 확정 예시 상태로 노출 |

**SKIP 허용**(`SKIP: [이유]` 기록 + 사용자 확인)은 ① 노드 ID 특정 불가 ② 다수 노드 불확실 ③ 플랫폼 분기 불명확 ④ variant 구조 불일치, 4경우뿐. 동기화 미반영 시 심볼(INSTANCE) 의심 → `figma-design` §G(전 인스턴스 스왑/detach) → 스크린샷 검증.

**동기화에 토큰·컴포넌트 매칭도 포함.** 디스크립션이 가리키는 입력/선택/바텀 액션 요소가 bespoke 도형이면 `figma-design` §L의 DS 컴포넌트(`use_form` 타입별·`btn54_main_set`)로 교체하고, 손작업 텍스트/색은 §K로 DS 변수에 바인딩한다(raw hex 잔존 0). 디스크립션 claim과 디자인이 같아도 토큰·컴포넌트가 bespoke면 미완료.

## 7. 완료 게이트 — 3자 매칭 (뱃지↔디스크립션↔디자인) claim↔노드 대조표 (필수 HITL · 단정 금지)
**"동기화 0건 / 이미 일치"는 그 자체로 완료 근거가 아니다.** 반드시 대조표로 증명한다. **대상은 대상 페이지의 모든 행** — 해피패스뿐 아니라 `storyboard-build` §6에서 추가한 **상세-케이스 화면(에러·empty·valid·로딩) 행도 포함**해 전 행을 대조한다(일부 행만 통과는 미완료).
- **절차**: 각 화면 annotation 본문에서 노출/상태/텍스트 claim(`미노출`·`노출`·`Default=Disabled`·`ON/OFF`·텍스트 값)을 전부 추출 → 각 claim의 **노드를 id로 조회**해 `visible`/variant/`characters` 실제값을 읽고 → **claim=실제 대조표** 작성.
- 불일치(✗) 1건이라도 있으면 미완료 → §6대로 수정하거나 SKIP+확인. **변경 0건이어도** 모든 claim=일치 ✓ 대조표를 **증거로 남겨야** 완료(표 없는 "0건" 보고는 미완료).
- 전형적 실패: 디스크립션엔 `visible=false` 인데 실제 노드는 `true` — "0건 일치"로 단정하면 못 잡는다. 대조 후에야 발견·수정.
- 이 대조표는 동기화 단계의 **출력 필수 산출물**. 작업 완료 시 사용자에게 대조표 + 스크린샷으로 보고.
- **★ 마감 = 리플로우 자동 실행(필수 게이트).** 디스크립션을 편집했으면 Description 높이가 바뀌므로, 작업을 끝내기 전 **`figma-design` §A 자동 발견 리플로우 루틴을 항상 실행**한다(SB 카드 height 리사이즈 + 전 행 Y cascade, 겹침 0). 사용자가 따로 요청하지 않아도 자동. 리플로우 매칭 카운트를 보고에 포함.
