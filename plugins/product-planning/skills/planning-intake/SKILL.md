# Planning Intake (티켓 인입 · 요건 파악)

워크플로우 1~2단계를 자동화한다. 노션 티켓을 가져와 이전 히스토리와 개발 요건을 파악하고, 이번 기획 작업의 워크스페이스 폴더를 만든다.

## 입력
- 노션 티켓 URL 또는 ID. 없으면 사용자에게 요청한다.

## 절차

1. **티켓 슬러그 결정**: `<YYYY-MM>-<짧은-영문-kebab-slug>` 형식. 제목에서 핵심어로 생성(예: `2026-06-coupon-policy-revamp`).

2. **engagement 폴더 생성** (현재 작업 디렉토리 기준, 플러그인 내부 아님):
   ```
   engagements/<slug>/
     research/
   ```

3. **티켓 fetch**: Notion MCP `notion-fetch` 로 티켓 본문을 가져온다. 본문에 연결된(멘션/링크된) 과거 티켓·문서가 있으면 추가로 `notion-fetch` 하여 **이전 히스토리**를 파악한다. 폭이 넓으면 `notion-search` 로 관련 과거 작업을 보강한다.

4. **00-ticket.md 작성**: `${CLAUDE_PLUGIN_ROOT}/templates/ticket.template.md` 를 읽어 채운다.
   - `요약`: 1~2문장.
   - `배경·이전 히스토리`: 연결 문서에서 파악한 맥락. **출처(노션 URL) 인용**.
   - `개발 요건`: 티켓에 명시된 요구사항을 **원문에 충실하게** 구조화. 추측 금지.
   - `프로젝트 유형`: 레거시 개선 vs 신규 — 후속 리서치 전략이 갈리므로 반드시 판정(불명확하면 사용자 확인).
   - 빈 항목은 `미상`으로 두고 `열린 질문`에 적는다.

5. **요약 보고**: 슬러그, 프로젝트 유형, 핵심 요건 3줄, 열린 질문을 사용자에게 보고하고 다음 단계(`domain-study`)를 제안한다.

## 원칙
- 티켓에 없는 내용을 지어내지 않는다. 모르는 것은 `열린 질문`으로.
- 산출물은 **항상 현재 작업 디렉토리**에 쓴다.
