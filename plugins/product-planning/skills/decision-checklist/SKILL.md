# Decision Checklist (의사결정 공백 · 추천안 · 임시 채택 · 최종 결정)

기획에 반드시 정해져야 하지만 **아직 알 수 없거나 결정되지 않은** 항목을 다루는 단일 방법론.
목표: 결정이 안 됐다고 작성을 멈추지 않고, **임시 채택안으로 작동하는 초안을 진행**하다가 **최종 결정 시 빠르게 본문을 교체**한다.
전략 결정을 대신 내리지 않는다 — **추천안 제시 + 임시 채택까지**가 역할이다.

## 1. 공백 식별 + 인라인 마커
- 본문 작성 중 정책/기획/기술 공백을 만나면, 해당 위치에 인라인 마커를 남긴다:
  `⛳추가 기획 필요 → D-n (임시: <임시 채택안>)`
- 같은 항목은 하나의 `D-n` 으로 묶고, 본문 여러 곳에서 같은 ID를 참조한다.

## 2. 추천안 제시 (복수)
- 각 공백에 **2~3개 추천안 + 트레이드오프**를 제시한다. 빅테크 관행·리서치(KB/research) 근거를 단다.
- 근거 없는 추천 금지. 불확실하면 "추정"으로 표시.

## 3. 임시 채택 → 초안 진행
- 추천안 중 하나를 **임시 채택**하고, 본문 초안을 그 기준으로 **완결성 있게** 작성한다(빈칸 방치 금지, 단 임시임을 마커로 명시).

## 4. 체크리스트 표 (단계별 산출물 하단에 내장 · 같은 스키마 공유)
아래 스키마를 그대로 사용한다. **추천안 컬럼과 임시 채택안 컬럼은 최종 결정 후에도 보존**한다(이력).
- **위치**: 기획 결정 = `PRD.md`/`SDD.md` C1. **디자인 결정(UX 배치·디자인 정책·플랫폼) = `policy-table.md` "디자인 의사결정 체크리스트"** — 같은 스키마. 디자인 단계는 PRD.md를 수정하지 않는다(핸드오프 동결 존중).
- **cross-link**: 디자인 결정이 제품 전략급(핵심밸류·타겟·서비스정책)이면 `영향 범위`에 `→ PRD D-n`으로 연결해 단일 원장으로 묶는다.

| ID | 결정 필요 항목 | 영역 | 추천안(트레이드오프) | 임시 채택안 | 결정 | 최종 결정안 | 영향 범위 |
|---|---|---|---|---|---|---|---|
| D-1 | (정해져야 하는 것) | 서비스정책 / 기획요건 / 기술요건 | A) …(장·단) · B) …(장·단) · C) … | A | ☐ | (미정) | FR-3, §7 |

- **영역**: `서비스정책` / `기획요건` / `기술요건`(기획) · `UX배치` / `디자인정책` / `플랫폼`(디자인) 중.
- **결정**: 미결 `☐`, 확정 `☑`.
- **영향 범위**: 이 결정이 반영되는 본문 위치(FR-n / US-n / 섹션). 최종 결정 시 수정 지점을 빠르게 찾기 위함.

## 5. 최종 결정 반영 플로우
사용자가 한 항목을 결정하면:
1. `최종 결정안` 컬럼에 결정 내용을 적고 `결정` 을 `☑` 로 (추천안·임시 채택안 컬럼은 **그대로 보존**).
2. `영향 범위` 의 FR/US/섹션을 찾아 **본문 초안을 임시 채택안 → 최종안으로 교체**.
3. 본문 인라인 마커(`⛳추가 기획 필요 → D-n`)를 갱신/제거.

## 원칙
- 결정 전 항목은 본문에 항상 `추가 기획 필요`로 가시화(숨기지 않는다).
- 표 스키마 변경은 개별 문서가 아니라 이 스킬에서 한다(단일 소스 — 기획·디자인 공통).
